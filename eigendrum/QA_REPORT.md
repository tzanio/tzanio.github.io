## Functional browser checks

- The 1× and 64× display-gain settings produced different canvas rasters while leaving the numerical state unchanged.
- The deterministic off-center strike materially excited **10 of 10** computed modes.
- Transient rendering did not mutate the stored first eigenvector.
- After strike expiration, the selected idle eigenmode was restored and remained visible.
- The last strike remained available for GLVis export after its on-screen response expired.
- Entering drawing mode synchronously cleared the prior mesh, solution, spectrum cards, field, and active response.
- A 44-point near-closed stroke auto-closed, was smoothed to 168 boundary samples, remeshed to exactly 400 interior DOFs, and solved for 10 modes.
- At a 390-pixel viewport, document scroll width remained 390 pixels and the main canvas remained 356 pixels wide.

## GLVis time-dependent export

The final packaged-site browser test exported:

- Frames: **72**.
- Physical interval: **9.08332421e-03 s**.
- Fundamental cycles: **2.000**.
- Physical sampling rate: **7816.522 Hz**.
- Highest exported modal frequency: **650.008 Hz**.
- Fastest-mode temporal resolution: **12 samples per period**.
- Playback rate: **24 fps**.
- Slow-motion factor: **325.69×**.

Each grid-function frame was generated by the same modal field evaluator used by the browser visualization. Unit tests compare exported nodal values directly with `evaluateStrikeAtNodes` at the recorded physical time. Exported fields are unscaled; the browser gain is recorded only as suggested GLVis color-range and vertical-stretch settings.

The generated archive passed:

- ZIP CRC/integrity checks;
- MFEM mesh and P1 grid-function presence checks;
- frame-count and metadata consistency checks;
- GLVis script solution-command count checks;
- Python player syntax compilation;
- a live TCP playback test against a mock GLVis socket receiver, which received all 72 solution streams and all 72 captions.

A desktop GLVis executable was not installed in the execution container, so a real OpenGL GLVis rendering session is not claimed.

This release does not include a precompiled MFEM WebAssembly binary because Emscripten was unavailable in the execution container. Browser QA therefore exercised the explicitly labeled matched P1 reference backend. The source archive contains the MFEM 4.9 C++ kernel and no-npm Emscripten build script; a genuine MFEM-WASM run is not claimed here.
