MFEM (web edition)

This workstation runs Linux on your device through WebAssembly. Bash, GCC, Make, Git and MFEM execute inside it. GitHub Pages serves static files. The GLVis pane uses the official GLVis WebAssembly renderer.

Use your computer for local compute

The header’s Local compute button opens setup instructions and a companion download. On a phone, it is in the ⋯ workspace menu. The companion serves this same Files, Editor, Terminal and GLVis interface from your laptop or desktop, while builds and simulations use its native compiler and MFEM checkout. The website cannot start a process on your computer automatically.

You need Python 3.12 or newer, Bash, Make, a C++17 compiler, and a serial or MPI MFEM 4.10 checkout configured and built with Make. The visualization helpers require its static libmfem.a. An MPI checkout also needs its usual MPI launcher and solver libraries. macOS is tested; Linux and WSL still need separate end-to-end validation. Native Windows is not supported.

  1. Download the local companion and unzip it.
  2. Open your computer’s terminal and change into the extracted folder containing companion/ and site/.
  3. Replace the path below with the absolute path to your native MFEM checkout, then run: 
    python3.12 companion/serve.py --workspace /absolute/path/to/mfem
  4. Open the localhost link printed by the companion. In that page’s Terminal pane, build and run normally: 
    make ex1
./ex1

The browser terminal is already connected to the native process. No separate xterm, X11 server or DISPLAY setting is needed. GLVis renders results in the browser. Keep the companion running while you work; closing or hiding the page leaves native jobs running. Reload the localhost page to reconnect. Terminal commands run with your local account’s permissions.

To create a fresh checkout, run the following in a parent directory of your choosing, then use the resulting absolute path with the companion:

git clone --branch v4.10 --depth 1 https://github.com/mfem/mfem.git mfem-local
cd mfem-local
make config MFEM_USE_MPI=NO MFEM_USE_METIS=NO
make -j4

With an existing MPI-enabled checkout, use the same companion command and run parallel examples in the browser terminal:

make ex1p
mpirun -np 2 ./ex1p

The native relay combines rank output for browser GLVis. Parallel mesh/solution visualization supports 1–64 ranks and one visualizing MPI job at a time; serial examples also work with an MPI checkout. Two-rank ex1p and time-dependent ex9p have been tested on macOS. The browser-only Linux environment remains serial.

Move existing work: use Export → Save & export changes in the browser-only page, then Import in the localhost page. Choose Full workspace instead when you also want saved tabs, layout, terminal output and displayed GLVis data. Local saves go directly to your checkout; unsaved editor drafts are retained separately in this browser. Export again from the local page to bring work back. Full imports retain the destination’s compiler configuration and build products, so rebuild imported code with make -B ex1 (or the affected target); force-rebuild the library too if its sources or headers changed. Exact GLVis cameras and running jobs are not transferred.

The download includes LOCAL_COMPUTE.md with diagnostics, alternate ports and platform limits. Phones and tablets continue using browser-only compute; their localhost address is their own device, not your laptop. The following Linux, prebuilt-example and browser-compiler instructions describe browser-only mode.

Run an example

The startup bar appears while the application downloads. It shows a progress bar, approximate megabytes remaining and elapsed time, then reports Linux boot and workspace restoration. It disappears once Linux and GLVis are ready. Files already cached in your browser count as available; compression and later file requests affect actual network traffic. If a download fails, a visible message offers Reload.

GLVis starts with saved results from the default ./ex1, labeled ex1 · saved result. No simulation runs at startup. Camera controls, PNG export and additional views work immediately; inspection becomes available once Linux is ready. Run ./ex1 yourself to replace the saved scene with a fresh result. The saved scene does not add live frames or recordings. The dot beside Alpine Linux is amber while starting, green when ready, and red if the runtime stops.

GLVis initializes while Linux boots, and selected startup files download in parallel. Large native guest files use compressed transport to reduce downloading; source files remain editable before Linux is ready. The browser title stays MFEM (web edition) when a visualization opens.

Wait for the workspace to show Saved before reloading. Export a backup before upgrading to a different base image. Content-versioned assets prevent a new page from mixing with an older cached guest image.

The terminal starts in /root/mfem/examples. All 37 targets selected by MFEM's default serial examples Makefile are already built, along with the shared and static MFEM libraries.

./ex1 -m ../data/star.mesh

Leave visualization enabled: the guest listens on localhost port 19916 and sends the solution to GLVis. Click the visualization before using keyboard shortcuts such as m for mesh and p for palette. No Cmd/Ctrl modifier is needed. Drag to rotate and scroll to zoom.

Watch a time-dependent solution

./ex9 -r 1 -o 2 -tf 0.08 -dt 0.01 -vs 1

Example 9 initially pauses its visualization. Click Resume, press Space with GLVis focused, or use Step to display one more frame. Frames then update while the example's socket remains open. Pause holds incoming frames; socket backpressure can also make the solver wait.

Open Controls for the mesh, axes, palette, colorbar, lighting, camera and zoom controls from web GLVis. The toolbar provides pause/resume, stepping, PNG export and fullscreen. Keyboard help shows the loaded renderer's key bindings. When an example opens several visualization connections, a field selector appears beside the GLVis title; choose the field you want to watch.

Compare, record and replay

Use + View to add up to four GLVis panes. Each pane has its own field selector, camera, palette and controls. Two panes can show the same field from different angles or different fields simultaneously. Pausing a field affects all panes watching that field; other connections continue independently.

In a pane's Controls, enable Fixed color range, enter Min and Max, then click Apply. These bounds remain fixed as later frames arrive. Applying a changed range initially resets that pane's scene; subsequent updates preserve its camera.

Click Record before starting a solve, or while it is running. The recorder keeps incoming solution frames in this tab, initially up to 32 MiB. Set Cap from 1 to 256 MiB. The oldest frames expire when the cap or 4,096-frame limit is reached; a frame larger than the cap is skipped. Stop recording to keep the retained frames without adding more.

Each pane has a frame slider, Replay at five frames per second, and Return live. Replay changes that pane only; incoming frames can continue recording. Frame history is temporary browser memory and is not included in workspace export. PNG export saves the currently displayed image.

Arrange your workspace

Drag the dividers beside Files, between the editor and GLVis, and above the terminal. Focus a divider and use arrow keys for keyboard adjustment, or double-click it to restore its default size. The Files button collapses the sidebar. Pane sizes and sidebar visibility are remembered in this browser.

The ⤢ button maximizes a pane; Escape restores the layout. Shortcuts: Alt+Shift+E for the editor, Alt+Shift+T for the terminal, Alt+Shift+V for GLVis and Alt+Shift+B to toggle Files. Layout preferences do not save guest files.

The header's Theme selector offers TMOG, Dark and Light, with TMOG selected by default. It follows the full-color TMOG console: charcoal surfaces, rounded inset panels, wide geometric headings and green, blue, purple and amber accents. The locally bundled Michroma font is used in headings. FILES, EDITOR and TERMINAL share the same caption styling; editor text and terminal output use monospace fonts. A soft glow accents the official MFEM logo. Syntax colors distinguish comments, keywords, types, definitions, strings, numbers and directives. Your choice is remembered. Retired phosphor preferences migrate to TMOG; saved Dark/Light choices are preserved. GLVis field colors stay unchanged.

Shortcuts, Controls, GLVis keyboard help, New file, search and Offline use compact movable windows. Drag a window by its title bar, or focus the title bar and use arrow keys. The other panes remain usable. Positions are kept while the page is open, and windows stay within the viewport when resized. Escape closes the top window; Escape then restores a maximized pane.

Inspect a mesh and solution

Click Inspect above a GLVis view. A movable window captures the displayed frame and reports mesh dimensions, element counts, element and boundary attributes, and element quality computed by MFEM. Refresh takes the latest displayed frame, including a replayed frame. The quality score is a sampled Jacobian singular-value ratio: 1 is ideal and 0 is degenerate. Sampling cannot prove validity everywhere in a curved element.

The inspector has an independent XY preview with element-quality or attribute coloring and boundary-attribute highlighting. Click it to probe a solution value, or enter physical coordinates. For a 3D mesh, set the Z coordinate of the probe plane. MFEM locates the element and evaluates the finite-element field directly. Shared-boundary points use the first containing element; discontinuous fields can have different neighboring values. Large previews are thinned but statistics include all elements. Serial mesh and solution streams are supported; complex solution values are not yet evaluated.

Edit and build

The editor automatically opens examples/ex1.cpp while Linux starts. You can edit immediately; saving becomes available when the dot beside Alpine Linux turns green. Save with the button or Ctrl/Cmd+S. Then rebuild and run:

make ex1
./ex1 -m ../data/star.mesh

Regular example builds automatically use a bundled GCC precompiled-header cache with the default -O2 -std=c++17 settings. Optimization stays unchanged. The compiler wrapper verifies header contents and actual preprocessing results before reuse, including header lookup changes caused by newly created files. Changed headers, custom flags or include environments use normal GCC instead. Source compilation and linking still run locally.

For faster iteration, build with mfem-build --fast --no-cache ex1. This uses -O0 and a separate validated header cache; the MFEM library stays optimized, but code in your example can run slower. Switch back with mfem-build --optimized ex1 before timing or long runs. Without --no-cache, the helper can reuse a matching previously built result after checking its inputs and profile. Ordinary make ex1 keeps its normal flags and timestamp checks, so it does not automatically replace an up-to-date fast binary. Each profile's first header-cache use downloads about 32 MB; complete Offline installation includes both.

MFEM_PCH_VERBOSE=1 make -W ex1.cpp ex1  # report whether the header cache is used
MFEM_PCH=0 make -W ex1.cpp ex1          # use ordinary GCC without the cache

After changing MFEM headers, run mfem-pch-build in the terminal to rebuild the optimized cache, or mfem-pch-build --fast for the iteration cache. Unset custom include/compiler environment variables first. The helper checks its inputs before and after compiling. User-generated caches live under /root/mfem/.mfem-build and can be saved with changed build outputs. mfem-build updates the parent library after source or header changes. For plain upstream example Makefiles, run make -C .. lib before rebuilding the example.

The editor has C++ highlighting, line numbers and independent file tabs. Use Find, Replace and Go to line, or Cmd/Ctrl+F, Cmd+Option+F / Ctrl+Shift+F, and Alt+G. Tab indents by three spaces; Shift+Tab outdents. Cmd/Ctrl+S saves the active tab and Cmd/Ctrl+Shift+S saves all changed tabs. Closing an edited tab asks whether to save or discard its changes.

Open another tab: click a different file in the Files tree. Each file keeps its own text, cursor and undo history. Click a tab to switch back. Create a file: click New file in the editor, enter a filename, and create the tab. Relative names use the current file's directory (initially /root/mfem/examples); an absolute path chooses another directory. The parent directory must already exist. Write your code and press Cmd/Ctrl+S to create the file in Linux. Files saved under /root/mfem appear in the Files tree and are included in workspace export; files elsewhere remain accessible from the terminal and editor. If that path already exists, the editor opens the existing file; a file created concurrently in the terminal is protected by the save check.

Open Shortcuts in the editor for the complete key list. With the editor focused: Alt+Shift+N opens New file, Alt+Shift+Left/Right switches tabs, Alt+Shift+W closes the active editor tab and Alt+Shift+K shows shortcuts. Cmd/Ctrl+/ toggles a line comment. Browser new-tab and close-tab shortcuts retain their usual behavior.

Clean tabs automatically reload changes made in the terminal. If both the editor and terminal changed a file, a banner keeps your editor text and offers Reload from disk or Overwrite disk. A normal save checks the file content again and stops if it changed. Click a compiler file.cpp:line:column location in the terminal to open that source line.

Symbols (Cmd/Ctrl+Shift+O) searches C++ declarations in the MFEM release and open buffers. Use Definition (F12 or Cmd/Ctrl+click) to navigate, Complete (Ctrl+Space) for identifier completion, and Back (Alt+Left) to return. Ambiguous names show candidate locations. This local index does not perform full compiler type, macro or template resolution. Open edited files replace their release declarations; unopened files use the bundled release index.

Use the ↻ Refresh button after creating, moving or deleting files in the terminal. Save editor changes before building.

cp ex1.cpp experiment.cpp
make experiment
./experiment -m ../data/star.mesh

git status
git diff

The full MFEM v4.10 checkout includes regular examples, miniapps, tests, data/ and Git metadata with shallow history. Rebuild the library with make -C /root/mfem. A complete rebuild takes time in an emulated machine.

A comfortable Bash terminal

The colored prompt shows the current directory and the exit status of a failed command. Directory listings, Git output and supported compiler diagnostics use colors. Press Tab to complete commands and filenames; make also completes example targets, git completes common subcommands and glvis completes its options.

Up/Down search command history, Ctrl+C interrupts a running command, and pasted text uses Bash's bracketed-paste handling. ll gives a detailed listing, .. moves up a directory and g is a shortcut for Git. You can edit directly with nano ex1.cpp or vim ex1.cpp.

To visualize saved files from the terminal:

glvis -m refined.mesh -g sol.gf
glvis -m ../data/star.mesh

The supplied glvis helper sends files to the browser viewer. It accepts -m, -g and -k.

Keep your work

The workspace button manages named saves in this browser on this device. Checkpoints include editor and terminal file changes, Git state, additions, renames, deletions, permissions, links and changed build outputs. Unsaved editor drafts are stored separately and recovered without writing them into Linux. Wait for Saved before closing; a running process is not saved.

Use the workspace window to create/switch names, recover the previous complete checkpoint or download a saved checkpoint. Saving uses an atomic generation, retaining the previous complete one. Errors and quota limits remain visible. You can omit/remove saved build outputs to reduce storage use. Clearing site data removes local saves; use Export → Full workspace for a portable backup or another device. A different base image requires explicit recovery or migration.

For a smaller source backup, choose Export → Save & export changes. It saves editor files first, then exports changes relative to the bundled MFEM 4.10 commit, including added, deleted and binary files. Ignored build outputs, Git history, layout and terminal state are omitted. Import accepts either type of archive. A changes-only import preserves unrelated edits but requires every affected file to match the base; a conflict or new-file collision rejects the whole patch without changing files.

Export and import show stages, elapsed time and measured progress in a movable Activity window. A finished export keeps its filename, size and Download again action; repeating the download reuses the ready archive. Failed operations offer Retry. Closing Activity keeps work running. Long file refreshes, mesh inspections and point probes also appear here.

Current full archives include an inventory that restores deletions and renames, plus changed build artifacts. Old archives remain overlay imports. Unsaved editor tabs survive an import. Saved-checkpoint .tar files restore into the matching base image.

Full workspace also saves theme, pane layout, expanded folders, editor tabs/order/selection/scroll, unsaved drafts, and the open editor-shortcuts and GLVis controls/help windows. Drafts stay separate from saved source files. Import keeps your current unsaved text; a conflicting imported draft opens in a separate recovery tab. Older archives still restore files only.

Retained terminal output preserves colors. Bash history and the directory within /root/mfem are restored at the next prompt: after importing, press Ctrl+C at the shell prompt to cancel any current input and apply the saved history and directory. Saved commands are never executed automatically. Running programs, unfinished commands and shell variables are not restored. Terminal output is bounded by retained scrollback and 4 MiB; history keeps up to its most recent 1 MiB.

Each GLVis view reopens its displayed dataset, title and fixed color range. Exact camera settings and animation history are not saved. Displayed datasets above the combined 16 MiB limit are omitted with a notice; their files under /root/mfem remain in the workspace archive. Import does not run a solver. Browser-local autosave still saves files and drafts; use Export → Full workspace to carry this session information to another browser.

Review and reproduce changes

Changes shows Git status and a patch relative to the shipped MFEM commit. Export changes captures committed, staged, unstaged and non-ignored untracked content, including binary files, permissions, links and deletions. It preserves your real staging index. The same source export is available through Export → Save & export changes. Use Import in either the browser-only or local-compute page to apply it after conflict checks. Alternatively, extract the archive and apply its patch to a clean checkout of the recorded base:

git apply --check /path/to/changes.patch
git apply --binary /path/to/changes.patch

The patch omits Git history and ignored build outputs. Reproduction adds a command, directory, selected meshes, test notes, runtime information and optional terminal scrollback. Review the downloaded bundle before sharing; the workstation does not send it anywhere.

Developer builds and tests

mfem-build --fast ex1
mfem-build --optimized --diagnose ex1
mfem-test '[Vector]'
mfem-test --list-tests
mfem-build --debug ex1
mfem-test --debug '[Vector]'

The native build helper checks the MFEM library first and can reuse an identical previously built example after validating source, includes, compiler, link inputs and profile. Use --no-cache to force compilation. Header dependencies are included for all prebuilt library objects and are updated after new includes. Restart solver processes after changing their library.

Result reuse costs time to validate. One local Chrome test took about 35 seconds for mfem-build --fast --no-cache ex1, 49 seconds for its first reusable fast build, 23–25 seconds to reuse an unchanged/reverted result, and 55 seconds for an optimized build. These are local observations, not device guarantees. For active edits, --no-cache avoids result-cache overhead while keeping the header cache. Add --diagnose for memory and build-phase measurements.

The serial Catch runner and test objects are prebuilt. The separate debug configuration under /root/mfem/.mfem-build/debug has MFEM_DEBUG=YES, symbols and -Og -g; its examples link that matching library. Native visualization helpers remain pinned to the shipped ABI.

GDB supports tested MFEM core inspection with matched debug symbols: ulimit -c unlimited, run the debug executable normally, then open a crash core with gdb ../.mfem-build/debug/examples/ex1 core. Use bt, select a numeric frame with frame N, then print mesh_file or list. Static software breakpoints also work. Live dynamic debugging and step/next are limited by v86's missing single-step trap support.

Optional browser compiler prototype

mfem-browser-build --optimized ex1
./ex1

This opt-in command runs Clang and the ELF linker directly in a browser worker, then installs the resulting program in Linux. First use downloads about 178 MB of compiler files with Activity progress. Ordinary startup does not download them. All compilation remains on your device.

The prototype supports a single C++ example, project headers under /root/mfem, the shipped serial configuration and --fast (-O0) or --optimized (-O2). It checks input consistency and preserves the previous executable on failure or Ctrl+C. Use the GCC/Make path for custom flags, external libraries, debug builds and unsupported constructs. The worker uses LLVM 23 and an older LLD 8 ELF linker; it is experimental.

One actual Chrome test compiled and linked edited ex1 in about 3–4 seconds inside WebAssembly. Complete commands took about 46 seconds on first use and 39 seconds warm, including native Make, input snapshots and checks. These local timings are not a device or network guarantee.

Included configuration and limits

  • Alpine Linux x86 with Bash, GCC 14, GNU Make, Git, Python 3, nano and Vim.
  • MFEM v4.10, serial CPU configuration, with its native Linux libraries and 37 prebuilt default serial example targets. The build manifest lists exact targets and hashes.
  • MPI and optional-library example sources are present, but those targets are not prebuilt. ex38 is prebuilt because upstream selects it; its integration methods still require LAPACK or Algoim and retain the upstream missing-dependency guards.
  • The GLVis bridge accepts serial streams up to 64 MiB per frame, with at most eight active connections. Each visualization pane chooses which connection to show.

This is a 32-bit emulated machine with 768 MiB of guest RAM. Compilation and large solves are slower than on a desktop. Start with small meshes and low refinement. MPI, CUDA, external solver packages and an X11 desktop are not preinstalled. Example options that request an unavailable backend require that backend to be built first.

All calculations stay on your device. Linux runs in a background worker so its computation does not occupy the editor's main JavaScript thread. This improves the opportunity for responsive input; it does not remove x86 emulation overhead. Files are downloaded from this site's host as needed, so first use requires a network connection. External guest networking is not configured: local Git commands work, while remote clone/fetch, package downloads and direct AI API calls from the guest need a separately configured network relay. No AI service or credentials are required. You can copy code to an AI tool and paste it back.

Use the workstation offline

Runtime filesystem files are cached as you use them. For a complete installation, open Offline and choose Download for offline use. The dialog shows the release size, available browser storage and progress. You can cancel and resume an incomplete download. Keep the tab open until it reports Offline ready.

The complete download includes the compiler, MFEM source/data/examples, editor and GLVis. It lets a fresh page boot and work without a connection. Clearing browser site data removes this installation. Offline files are the supplied tools; named workspace checkpoints separately preserve your changes. Keep portable exports as backups. Use HTTPS or localhost for offline support.

Using a phone or tablet

On phones, use the bottom Files / Editor / GLVis / Terminal tabs to give one pane the full screen. GLVis opens first; opening a file switches to the editor. The ⋯ menu contains workspace actions, Activity, Offline, Local compute and themes. The visualization toolbar scrolls if needed. Record reveals recording options; the camera selector switches between added views. Drag the scene with one finger or pinch to zoom. Expand visualization fills the browser viewport if browser fullscreen is unavailable. Tablet and desktop widths retain the split layout.

Responsive phone/tablet sizing and the real GLVis canvas are tested in Chromium and WebKit, including portrait, landscape and pane resizing. Safari and Chrome should use the same phone layout. Physical iPhone and iPad compatibility, memory limits and on-screen keyboard behavior still need device testing. The VM reserves 768 MiB before browser and GLVis overhead. Start with a small prebuilt example and one visualization; a physical keyboard makes editing and terminal commands easier. Keep active calculations in the foreground and wait for Saved before leaving, or export a backup. The optional browser compiler uses additional memory; start with prebuilt examples on small devices.

Deploy on GitHub Pages

Publish the distribution's site/ directory with GitHub Pages. Keep every asset and the directory structure, including vm/files-index.json, offline-manifest.json, service-worker.js and the filesystem blobs. Relative URLs work for personal and project Pages. The supplied Actions workflow deploys the site directory. No compute server, custom response headers or secret keys are needed.

The packaged scripts/deploy-pages.py helper can add MFEM under an existing static Pages site while preserving other pages. From the directory containing mfem-desktop/, with GitHub CLI authenticated:

python3 mfem-desktop/scripts/deploy-pages.py --repo tzanio/tzanio.github.io --path mfem --publish

This publishes to https://tzanio.github.io/mfem/. Omit --publish to prepare a local checkout for review. Existing Actions or Jekyll sites must use their existing build process. Details and prerequisites are in the packaged README.
